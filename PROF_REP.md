## 2. Анализ perf report для связного списка — какие функции оказались в топе и почему именно они.
В топе оказалась функция strcmp по причине того, что список при поиске проверяет каждый узел на совпадение кода.
Также следующая за ней оказалась listFind по причине того, что она активно использует является основной для поиска и использует strcmp.

## 3. Объяснение разницы

На команде find в авл каждое сравнение в узле отсекает ровно половину поискового пространства. Список же вынужден идти линейно по всем элементам подряд пока не найдет нужный.
В авл поиск занимает О(log(n)), в списке O(n). Для команды insert все меняется в том случае, если вставка в список происходит каждый раз в его начало, тогда ассимптотика вставки будет О(1).
Но на чистой операции find авл опережает список.

## 4. Вывод 

По результатам тестирования системы регистрации рейсов, я рекомендую использовать АВЛ-дерево как основной способ организации данных. Данное решение обеспечивает стабильно высокую скорость поиска даже при пиковых нагрузках, позволяя обрабатывать запросы как минимум в несколько раз быстрее текущей реализации на базе списков.
